# Пакетный Конфигуратор: база данных и конфигурация

← [К оглавлению](README.md) · Назад: [Общие параметры](02-common-parameters.md) · Дальше: [Проверки и файлы поставки](04-configurator-batch-advanced.md)

## Общие правила

- Пакетный режим включается режимом `DESIGNER` + [общие команды](02-common-parameters.md) + одна команда пакетного запуска. Пример:

  ```
  1cv8 DESIGNER /IBName "My db" /DumpIB c:\temp\dump.dt
  ```

- Команды пакетного режима **не комбинируются** в одной строке, если явно не сказано иное.
- Если параметр требует имя файла с полным путем — все каталоги пути должны существовать, иначе операция не выполнится.
- Модули, для доступа к которым требуется пароль, в пакетном режиме игнорируются (формируется диагностическое сообщение).
- `-Extension` и `-AllExtensions` одновременно не указываются (поведение не определено).
- Код возврата: `0` — успех, `1` — ошибки (текст — в файл служебных сообщений).

## Выгрузка/загрузка базы данных

| Команда | Описание |
| --- | --- |
| `/DumpIB <имя файла>` | Выгрузить информационную базу в файл |
| `/RestoreIB <имя файла> [-JobsCount <количество>]` | Загрузить базу из файла. `-JobsCount` — число системных фоновых заданий (по умолчанию 0 = столько, сколько процессоров). Ускорение достигается, когда кластер серверов и СУБД на одной машине и связаны каналом ≥ 1 Гбит |

## Восстановление структуры базы

`/IBRestoreIntegrity` — попытка восстановить структуру информационной базы. Другие параметры игнорируются. Результат — в файл `/Out`:

- «Восстановление информационной базы не требуется» — структура не нарушена (код возврата 0);
- «Информационная база успешно восстановлена» (код возврата 0);
- текст ошибки (код возврата 1).

Рекомендуется, если предыдущее обновление конфигурации базы не завершилось (аварийное завершение Конфигуратора, выключение компьютера).

## Конфигурация и расширения

### Базовые операции с конфигурацией

| Команда | Описание |
| --- | --- |
| `/DumpCfg <имя cf/cfe файла> [-Extension <имя>]` | Сохранить конфигурацию (или расширение при `-Extension`) в файл |
| `/LoadCfg <имя cf/cfe файла> [-Extension <имя>]` | Загрузить конфигурацию (или расширение) из файла. Если расширения нет в базе — оно создается. Загрузка расширения, подключенного к хранилищу конфигурации, невозможна |
| `/RollbackCfg [-Extension <имя>]` | Возврат к конфигурации базы данных (для расширения — при `-Extension`) |
| `/DeleteCfg [-Extension <имя>] [-AllExtensions]` | Удалить расширение (все — при `-AllExtensions`). Без параметров команда не допускается |
| `/DumpDBCfg <имя cf/cfe файла> [-Extension <имя>]` | Сохранить конфигурацию базы данных (или конфигурацию расширения из базы) в файл |
| `/DumpDBCfgList [-Extension <имя>] [-AllExtensions]` | Вывести имя основной конфигурации (без параметров) или имя/имена расширений |
| `/GetConfigGenerationID [-Extension <имя>]` | Идентификатор «поколения» метаданных (обновляется при любом изменении конфигурации). Сравнивать только на «равно/не равно». Требует `/Out`. Пример: `4d8d1d994cd4534c9accd32a5b44b35300000000`; для пустой ИБ — `0000000000000000000000000000000000000000` |

### Объединение конфигураций

`/MergeCfg <имя cf- или cfe-файла> -Settings <имя файла настроек> [-EnableSupport | -DisableSupport] [-IncludeObjectsByUnresolvedRefs | -ClearUnresolvedRefs] [-Extension <имя>] [-force]`

Объединение текущей конфигурации (или расширения) с файлом по файлу настроек.

| Параметр | Описание |
| --- | --- |
| `-Settings <файл>` | Файл настроек объединения (формат — в официальной документации) |
| `-EnableSupport` | Поставить конфигурацию на поддержку, если есть возможность (правила — в файле настроек) |
| `-DisableSupport` | Не ставить на поддержку, даже если есть возможность |
| `-IncludeObjectsByUnresolvedRefs` | Повторно помечать для объединения объекты, на которые есть ссылки из включенных объектов (аналог кнопки «Пометить все для объединения» с повторением попыток) |
| `-ClearUnresolvedRefs` | Очищать ссылки на объекты, не включенные в объединение (аналог кнопки «Продолжить») |
| `-force` | Продолжать объединение при предупреждениях об удаляемых объектах со ссылками (они исключаются) и о применении настроек. Без `-force` объединение прерывается |

Ограничения:

- `-EnableSupport`/`-DisableSupport` несовместимы с `-Extension` (прерывание с ошибкой).
- Если возможна постановка на поддержку, но не указан ни `-EnableSupport`, ни `-DisableSupport` — прерывание с ошибкой (и наоборот).
- При `-EnableSupport` без элемента SupportRules в настройках применяются правила по умолчанию: новые/идентичные объекты и объекты «Взять из новой конфигурации поставщика» → «Объект поставщика не редактируется» (для «Изменения разрешены» и «Изменения не рекомендуются»); измененные объекты с другим правилом объединения → «Объект редактируется с сохранением поддержки».
- Неразрешенные ссылки во второй конфигурации без `-IncludeObjectsByUnresolvedRefs`/`-ClearUnresolvedRefs` — прерывание; в файл сообщений выводится список свойств с неразрешенными ссылками и не включенных объектов. Предупреждения выводятся независимо от `-force`.

### Сравнение конфигураций

`/CompareCfg` — сравнение двух конфигураций с формированием отчета.

```
/CompareCfg -FirstConfigurationType <тип> [-FirstName <имя>] [-FirstFile <путь>] [-FirstVersion <версия>]
            -SecondConfigurationType <тип> [-SecondName <имя>] [-SecondFile <путь>] [-SecondVersion <версия>]
            [-MappingRule <правило>] [-Objects <файл>] -ReportType <тип>
            [-IncludeChangedObjects] [-IncludeDeletedObjects] [-IncludeAddedObjects]
            -ReportFormat <формат> -ReportFile <имя файла>
```

Тип конфигурации (для обеих сторон):

| Значение | Что сравнивается |
| --- | --- |
| `MainConfiguration` | Основная конфигурация |
| `DBConfiguration` | Конфигурация базы данных |
| `VendorConfiguration` | Конфигурация поставщика (имя — в `-FirstName`/`-SecondName`) |
| `ExtensionConfiguration` | Расширение конфигурации (имя — в `-Name`) |
| `ExtensionDBConfiguration` | Расширение из базы данных (имя — в `-Name`) |
| `ConfigurationRepository` | Конфигурация из хранилища (версия — в `-Version`) |
| `ExtensionConfigurationRepository` | Расширение из хранилища (имя + версия) |
| `File` | Файл .cf/.cfe (путь — в `-File`) |

Остальные параметры:

| Параметр | Описание |
| --- | --- |
| `-MappingRule <правило>` | Правило соответствия объектов, если конфигурации не в отношениях «родитель-потомок»: `ByObjectName` (по умолчанию), `ByObjectIDs` |
| `-Objects <файл>` | Файл со списком участвующих объектов (без него — вся конфигурация) |
| `-IncludeChangedObjects` / `-IncludeDeletedObjects` / `-IncludeAddedObjects` | Включать в отчет измененные/удаленные/добавленные подчиненные объекты |
| `-ReportType <тип>` | `Brief` — краткий отчет; `Full` — полный |
| `-ReportFormat <формат>` | `txt` — текстовый документ; `mxl` — табличный документ |
| `-ReportFile <имя>` | Файл отчета |

### Обновление конфигурации базы данных

`/UpdateDBCfg` — обновление конфигурации базы данных (реструктуризация). Перед реструктуризацией проверяется подпись мобильного клиента. Диагностические сообщения по умолчанию — предупреждения (не блокируют обновление).

```
/UpdateDBCfg [-Dynamic<режим>] [-BackgroundStart] [-BackgroundCancel] [-BackgroundFinish [-Visible]]
             [-BackgroundSuspend] [-BackgroundResume] [-WarningsAsErrors] [-Server]
             [-v1|-v2] [-Extension <имя>] [-SessionTerminate <режим>]
```

| Параметр | Описание |
| --- | --- |
| `-Dynamic<режим>` | Динамическое обновление: `-` — явно запрещено; `+` — разрешено (сначала обычное, при неудаче — динамическое). Динамическое разрешено и без параметра |
| `-BackgroundStart` | Запустить фоновое обновление и завершить работу (при `-Dynamic+` — сначала попытка динамического) |
| `-BackgroundCancel` | Отменить запущенное фоновое обновление |
| `-BackgroundFinish` | Завершить фоновое обновление (фаза принятия изменений): монополирование базы и финальная фаза. `-Visible` — диалог «Отмена/Повторить/Завершить сеансы и повторить» при невозможности; без флага — завершение с ошибкой |
| `-BackgroundSuspend` / `-BackgroundResume` | Приостановить / продолжить фоновое обновление |
| `-WarningsAsErrors` | Все предупреждения трактовать как ошибки |
| `-Server` | Выполнять обновление на сервере (клиент-серверный вариант). С фоновым обновлением: фаза актуализации всегда на сервере; фаза обработки и принятия изменений — на клиенте или сервере; допустим запуск на клиенте и завершение на сервере (и наоборот). Оптимизированный механизм (`-v2`) не используется |
| `-v1` / `-v2` | Механизм реструктуризации: обычный / оптимизированный. Без указания — версия из параметра UpdateDBCfg файла conf.cfg. При конфликте оптимизированного механизма с другими параметрами используется обычный |
| `-Extension <имя>` | Обновить указанное расширение |
| `-SessionTerminate <режим>` | Завершение активных сеансов при необходимости эксклюзивной блокировки: `disable` — не завершать (по умолчанию); `force` — принудительно завершать |

Фоковое обновление не связано с выбором механизма реструктуризации: при фоновом обновлении `-v1`/`-v2` игнорируются.

`/UpdateDBCfg` допускается указывать **после** команд: `/LoadCfg`, `/UpdateCfg`, `/ConfigurationRepositoryUpdateCfg`, `/LoadConfigFiles`, `/LoadConfigFromFiles`, `/MobileAppUpdatePublication`, `/MobileAppWriteFile`, `/MobileClientDigiSign`, `/MobileClientWriteFile`.

### Выгрузка/загрузка отдельных свойств объектов

`/DumpConfigFiles <каталог> [-Module] [-Template] [-Help] [-AllWritable] [-Picture] [-Right] [-Extension <имя>]` — выгрузить свойства объектов (модули, макеты, справка, общие картинки, права) в файлы.

`/LoadConfigFiles <каталог> [-Module] [-Template] [-Help] [-AllWritable] [-Picture] [-Right] [-Extension <имя>]` — загрузить свойства из файлов.

| Параметр | Описание |
| --- | --- |
| `-Module` | Модули |
| `-Template` | Макеты |
| `-Help` | Справочная информация |
| `-AllWritable` | Только объекты, доступные для записи |
| `-Picture` | Общие картинки |
| `-Right` | Права доступа |
| `-Extension <имя>` | Для/в указанное расширение. При загрузке в расширение, подключенное к хранилищу, загружаемые объекты должны быть захвачены в хранилище |

Код возврата: `0` — успех; `1` — ошибка (`101`, если в данных имеются ошибки).

### Выгрузка/загрузка конфигурации в файлы (XML)

#### /DumpConfigToFiles

```
/DumpConfigToFiles <каталог> [-Format <режим>] [-Extension <имя>] [-AllExtensions] [-update] [-force]
                   [-getChanges <файл>] [-configDumpInfoForChanges <файл>] [-listFile <файл>]
                   [-configDumpInfoOnly] [-Server [-JobsCount <количество>]] [-Archive <файл>]
                   [-ignoreUnresolvedReferences]
```

| Параметр | Описание |
| --- | --- |
| `-Format <режим>` | `Plain` — плоский формат; `Hierarchical` — иерархический (по умолчанию) |
| `-Extension <имя>` | Выгрузить указанное расширение |
| `-AllExtensions` | Выгрузить все расширения (каждое в каталог со своим именем); основная конфигурация не выгружается |
| `-update` | Обновить ранее сделанную выгрузку: только объекты с изменившимися версиями. Файл версий ConfigDumpInfo.xml берется из каталога выгрузки; при несовпадении версий формата — ошибка (см. `-force`) |
| `-force` | При несовпадении версии формата — полная выгрузка (только с `-update`) |
| `-getChanges <файл>` | Сформировать список изменений текущей конфигурации относительно выгрузки (файла версий). Совместим с `-configDumpInfoForChanges` |
| `-configDumpInfoForChanges <файл>` | Файл версий для сравнения (только с `-update` и `-getChanges`); не изменяется |
| `-listFile <файл>` | Выгрузить объекты из списка независимо от изменений (только отдельно от других параметров). Подчиненные объекты-отдельные объекты разработки выгружаются только при явном указании; внешние свойства подчиненных объектов выгружаются. Допустим идентификатор `Configuration` (эквивалент корня): `Configuration.Help` ≡ `Configuration.ИмяКонфигурации.Help` |
| `-configDumpInfoOnly` | Сформировать только файл версий (совместим только с `-Format`; по умолчанию — иерархический формат) |
| `-Server [-JobsCount <N>]` | Выгрузка на стороне сервера (многопоточно, быстрее). `-JobsCount` — число фоновых заданий (0 = автоматически по ядрам) |
| `-Archive <файл>` | Выгрузить в zip-архив (полная/частичная выгрузка, только файл версий, все расширения) |
| `-ignoreUnresolvedReferences` | Не выгружать ссылки на недостижимые (удаленные в прошлых версиях) объекты: ссылки на команды в управляемых формах заменяются на ссылку по умолчанию; недостижимые ссылки на группы команд, пути к данным, предопределенные элементы, связи параметров/типов — не выгружаются; в командном интерфейсе подсистем группы команд заменяются на `ПанельНавигацияОбычное`. Последующая загрузка такого XML может привести к очистке внешнего свойства |

#### /LoadConfigFromFiles

```
/LoadConfigFromFiles <каталог> [-Extension <имя>] [-AllExtensions] [-files "<файлы>"]
                     [-listFile <файл>] [-Format <режим>] [-updateConfigDumpInfo] [-NoCheck]
                     [-Archive <имя ZIP-архива>] [-partial]
```

| Параметр | Описание |
| --- | --- |
| `-Extension <имя>` | Загрузить в указанное расширение (создается, если нет). Полная загрузка расширения, подключенного к хранилищу, не поддерживается; частичная — возможна, если объекты захвачены |
| `-AllExtensions` | Загрузить расширения: каждый подкаталог — отдельное расширение. Несовместим с `-files`/`-listFile` |
| `-files "<файлы>"` | Частичная загрузка: список файлов (полный или относительный путь), в кавычках, через запятую |
| `-listFile <файл>` | Файл со списком загружаемых файлов (по одному имени на строку, UTF-8, без пустых строк; строки, начинающиеся с REM, пропускаются) |
| `-Format <режим>` | `Plain` / `Hierarchical` (по умолчанию). Только с `-files`/`-listFile` (при полной загрузке формат определяется автоматически) |
| `-updateConfigDumpInfo` | В конце загрузки создать/обновить ConfigDumpInfo.xml |
| `-NoCheck` | Не проверять целостность загружаемой конфигурации (быстрее) |
| `-Archive <архив>` | Загрузка из ZIP-архива (вместо каталога; одновременно указывать нельзя) |
| `-partial` | Загружать только те элементы описания объекта, которые указаны как файлы (описание объекта без внешних свойств; файл внешнего свойства; файл модуля формы без описания формы) |

При одновременном `-files` и `-listFile` используется первый в командной строке. Загрузка расширения в основную конфигурацию (и наоборот) не поддерживается.
