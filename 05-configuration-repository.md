# Хранилище конфигурации

← [К оглавлению](README.md) · Назад: [Проверки и файлы поставки](04-configurator-batch-advanced.md) · Дальше: [Режим агента](06-agent-mode.md)

Хранилище конфигурации — механизм контроля изменений конфигурации: версии, захват объектов, пользователи с правами. Все команды работают в режиме `DESIGNER`.

Почти все команды поддерживают параметр `-Extension <имя расширения>` — операция выполняется с хранилищем указанного расширения; без параметра — с хранилищем основной конфигурации.

Код возврата пакетного режима: `0` — нет ошибок; `1` — есть ошибки (текст — в файл служебных сообщений).

## Доступ к хранилищу

Команды доступа могут сочетаться с любыми другими командами хранилища.

| Команда | Описание |
| --- | --- |
| `/ConfigurationRepositoryF <каталог>` | Путь к хранилищу конфигурации |
| `/ConfigurationRepositoryN <имя>` | Имя пользователя хранилища |
| `/ConfigurationRepositoryP <пароль>` | Пароль пользователя хранилища |

## Создание хранилища

```
/ConfigurationRepositoryCreate [-AllowConfigurationChanges]
                               [-ChangesAllowedRule <правило>] [-ChangesNotRecommendedRule <правило>]
                               [-NoBind] [-MinPasswordLenght <длина>] [-CheckPasswordComplexity]
                               [-Extension <имя>]
```

| Параметр | Описание |
| --- | --- |
| `-AllowConfigurationChanges` | Если конфигурация на поддержке без возможности изменения — включить возможность изменения |
| `-ChangesAllowedRule <правило>` | Правило поддержки для объектов, где изменения разрешены поставщиком |
| `-ChangesNotRecommendedRule <правило>` | Правило поддержки для объектов, где изменения не рекомендуются |
| `-NoBind` | Не выполнять подключение к созданному хранилищу |
| `-MinPasswordLenght <длина>` | Минимальная длина пароля |
| `-CheckPasswordComplexity` | Включить проверку сложности пароля |
| `-Extension <имя>` | Создать хранилище для расширения (без параметра — для основной конфигурации) |

Допустимые правила поддержки:

| Значение | Правило |
| --- | --- |
| `ObjectNotEditable` | Объект поставщика не редактируется |
| `ObjectIsEditableSupportEnabled` | Объект поставщика редактируется с сохранением поддержки |
| `ObjectNotSupported` | Объект поставщика снят с поддержки |

## Пользователи

### /ConfigurationRepositoryAddUser

```
/ConfigurationRepositoryAddUser -User <имя> -Pwd <пароль> -Rights <права>
                                [-RestoreDeletedUser] [-Extension <имя>]
```

Создать пользователя хранилища. Подключающийся пользователь должен иметь административные права. Если пользователь с таким именем существует — не добавляется.

| Параметр | Описание |
| --- | --- |
| `-User <имя>` | Имя создаваемого пользователя |
| `-Pwd <пароль>` | Пароль (проверяется по политикам паролей хранилища) |
| `-Rights <права>` | `ReadOnly` — просмотр; `LockObjects` — захват объектов; `ManageConfigurationVersions` — изменение состава версий; `Administration` — административные функции |
| `-RestoreDeletedUser` | Восстановить удаленного пользователя с таким именем, если найден |

### /ConfigurationRepositoryCopyUsers

```
/ConfigurationRepositoryCopyUsers -Path <путь> -User <имя> -Pwd <пароль>
                                  [-RestoreDeletedUser] [-Extension <имя>]
```

Копировать пользователей из другого хранилища. Удаленные пользователи не копируются; существующие — не добавляются. `-Path`/`-User`/`-Pwd` — доступ к хранилищу-источнику.

## Операции с объектами

Во всех трех командах `-Objects <файл>` — файл со списком участвующих объектов (без него — вся конфигурация).

### /ConfigurationRepositoryLock — захват

```
/ConfigurationRepositoryLock [-Objects <файл>] [-revised] [-Extension <имя>]
```

Захватить объекты из хранилища для редактирования. `-revised` — получать захваченные объекты, если потребуется.

### /ConfigurationRepositoryUnLock — отмена захвата

```
/ConfigurationRepositoryUnLock [-Objects <файл>] [-force] [-Extension <имя>]
```

| Параметр | Поведение |
| --- | --- |
| `-force` указан | Локально измененные объекты получаются из хранилища — **изменения теряются** |
| `-force` не указан | При наличии локальных изменений — ошибка, операция отменяется целиком |

### /ConfigurationRepositoryCommit — помещение изменений

```
/ConfigurationRepositoryCommit [-Objects <файл>] [-comment <текст>] [-keepLocked] [-force] [-Extension <имя>]
```

| Параметр | Описание |
| --- | --- |
| `-comment <текст>` | Комментарий к помещаемым объектам (в двойных кавычках; многострочный — каждой строкой свой `-comment`) |
| `-keepLocked` | Оставить объекты захваченными (без флага захват отменяется) |
| `-force` | При ссылках на удаленные объекты: с флагом — попытка очистки ссылок; без — ошибка |

## Операции со всей конфигурацией

### /ConfigurationRepositoryBindCfg — подключение к хранилищу

```
/ConfigurationRepositoryBindCfg [-forceBindAlreadyBindedUser] [-forceReplaceCfg] [-Extension <имя>]
```

Подключить ранее неподключенную базу к хранилищу конфигурации.

| Параметр | Описание |
| --- | --- |
| `-forceBindAlreadyBindedUser` | Подключать, даже если у пользователя уже есть конфигурация, связанная с этим хранилищем |
| `-forceReplaceCfg` | Если конфигурация непустая — подтвердить замену конфигурацией из хранилища |

### /ConfigurationRepositoryUnbindCfg — отключение

```
/ConfigurationRepositoryUnbindCfg [-force] [-Extension <имя>]
```

Отключить конфигурацию от хранилища (нужны административные права в базе). Если пользователь аутентифицирован в хранилище (интерактивно или через командную строку) — отключение отражается и в самом хранилище (информация о подключении удаляется); иначе — только локальное отключение.

Если в конфигурации есть захваченные объекты, измененные относительно хранилища, — выводится сообщение и отключение не выполняется.

`-force` — пропустить диалог аутентификации (если не указаны параметры пользователя хранилища) и игнорировать захваченные измененные объекты.

### /ConfigurationRepositoryDumpCfg — сохранение из хранилища в файл

```
/ConfigurationRepositoryDumpCfg <имя cf-файла> [-v <номер версии>] [-Extension <имя>]
```

`-v` — номер версии (без указания или `-1` — последняя).

### /ConfigurationRepositoryUpdateCfg — обновление из хранилища

```
/ConfigurationRepositoryUpdateCfg [-v <номер версии>] [-revised] [-force]
                                  [-Objects <файл>] [-Extension <имя>]
```

| Параметр | Описание |
| --- | --- |
| `-v <версия>` | Версия из хранилища. Если конфигурация подключена к хранилищу — номер игнорируется, получается актуальная версия. Если не подключена — получается указанная версия (без указания или `-1` — актуальная) |
| `-revised` | Получать захваченные объекты, если потребуется (игнорируется, если не подключено) |
| `-force` | Подтвердить получение новых объектов или удаление существующих при пакетном обновлении. Без флага действия не выполняются |
| `-Objects <файл>` | Файл со списком участвующих объектов |

## Сервисные операции

### /ConfigurationRepositorySetLabel — метка версии

```
/ConfigurationRepositorySetLabel [-v <номер версии>] [-name <имя метки>]
                                 [-comment <текст>] [-Extension <имя>]
```

| Параметр | Описание |
| --- | --- |
| `-v <версия>` | Версия, для которой ставится метка (без указания — последняя; несуществующая — ошибка) |
| `-name <имя>` | Текст метки (в двойных кавычках) |
| `-comment <текст>` | Комментарий (в двойных кавычках; многострочный — каждой строкой свой `-comment`) |

### /ConfigurationRepositoryReport — отчет по истории

```
/ConfigurationRepositoryReport <имя файла> [-NBegin <версия>] [-NEnd <версия>]
                               [-DateBegin <дата>] [-DateEnd <дата>] [-GroupByObject] [-GroupByComment]
                               [-DoNotIncludeVersionsWithLabels] [-IncludeOnlyVersionsWithLabels]
                               [-IncludeCommentLinesWithDoubleSlash] [-ConfigurationVersion <версия>]
                               [-ReportFormat <txt|mxl>] [-Extension <имя>]
```

Отчет по истории хранилища. Без параметров группировки и при режиме совместимости «Не использовать» — группировка по версиям; в режимах 8.1 и 8.2.13 — по объектам. Если конфигурация базы отличается от редактируемой по совместимости — учитывается режим конфигурации базы.

| Параметр | Описание |
| --- | --- |
| `<имя файла>` | Файл отчета |
| `-NBegin` / `-NEnd` | Номер версии начала/окончания отчета (`-1` — последняя версия) |
| `-DateBegin` / `-DateEnd` | Даты начала/окончания (синтаксис строки конструктора типа Дата) |
| `-GroupByObject` | Группировка по объектам |
| `-GroupByComment` | Группировка по комментарию |
| `-DoNotIncludeVersionsWithLabels` | Не включать версии с метками |
| `-IncludeOnlyVersionsWithLabels` | Только версии с метками (игнорируется при `-DoNotIncludeVersionsWithLabels`) |
| `-IncludeCommentLinesWithDoubleSlash` | Включать строки комментариев, начинающиеся с `//` |
| `-ConfigurationVersion <версия>` | Версия конфигурации, для которой формируется отчет |
| `-ReportFormat <формат>` | `txt` — текстовый файл; `mxl` — табличный документ (по умолчанию) |

### /ConfigurationRepositoryOptimizeData

```
/ConfigurationRepositoryOptimizeData [-Extension <имя>]
```

Оптимизация хранения данных в хранилище конфигурации.

## Кеш хранилища

| Команда | Описание |
| --- | --- |
| `/ConfigurationRepositoryClearCache [-Extension <имя>]` | Очистка локальной базы данных хранилища конфигурации |
| `/ConfigurationRepositoryClearLocalCache [-Extension <имя>]` | Очистка локального кеша версий конфигурации |
| `/ConfigurationRepositoryClearGlobalCache [-Extension <имя>]` | Очистка глобального кеша версий конфигурации |
